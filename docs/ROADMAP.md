# Roadmap

## Phase 0 — 集中启动（当前）

- 建立独立工作区、治理边界和来源迁移清单。
- 迁移最小Pose/跟踪/渲染/动作稳定底座和真实ONNX模型。
- 完成真实短片到原创Web界面的离线链路。
- 建立对象、交互、时序动作、工序接口以及数据Schema。
- 用专项测试、真实短片轻量检查和compileall收口。

## Phase 1 — 人工本体与复核闭环

- 用户确认零件类、工具类、动作边界和工序命名。
- 建立逐事件复核UI，保留 reviewer/reviewed_at/training_approval。
- 对sample_set_A/sample_set_B、sample_set_C按录制组管理，继续保持split未分配。
- 标注遮挡、可见性、左右侧与“不足以判断”的负例。

## Phase 2 — 真实零件检测与跟踪

- 选择有授权且覆盖目标零件的检测模型或采集训练数据。
- 版本化object模型和类别表，评估mAP、per-class P/R、track continuity。
- 验证遮挡恢复，禁止用Pose框冒充零件框。

## Phase 3 — 派生交互与数秒动作

- 标定腕点—零件框关联阈值和左右侧错误率。
- 使用数秒上下文建模动作，而非逐帧命名。
- 评估动作Macro-F1、边界误差、过度分割与lost误报。

## Phase 4 — 工序候选

- 以动作、零件和时间顺序生成可解释步骤候选。
- 支持漏步骤、重复和顺序异常的技术证据，但不产生生产判定。
- 评估步骤准确率、边界、顺序、重复识别和不确定覆盖率。

## Phase 5 — 外部工厂验证

- 新增至少第三个独立录制组，再设计按组的train/dev/test。
- 在目标相机、光线、遮挡和节拍下独立验证。
- 只有外部验证完成并有书面准入，才讨论更改四个false标志。
